# 客户端延迟跳转 + 历史记录劫持（技术笔记）

> 记录日期：2026-08-03  
> 样本域名（当时实测）：`www.blog.wdgxlsu.com` → `qs88.hbedwde.cn/12.html`  
> 本地可复现演示：`demo/`（`http://127.0.0.1:8765/`）

本文记录一类常见黑产 / 导流站的跳转手法：**不是 HTTP 301/302**，而是「入口壳页 + 外链 JS 延迟跳转 + 落地页后退劫持」。便于以后做识别、过滤或安全审计时对照。

---

## 1. 整体链路

```text
用户打开入口域名
    │
    ▼
服务器返回 200 + 几乎空白的 HTML（标题常为「正在加载…」）
    │
    ▼
页面加载外域脚本（统计 + 跳转）
    │
    ▼
setTimeout(N ms) → window.location.href = 落地页
    │
    ▼
落地页 history.pushState(..., '#')
    │
    ▼
用户点「后退」→ popstate → 强制跳到另一个导流页
```

| 环节 | 手段 | 典型目的 |
|------|------|----------|
| 入口 | `200` 壳页 + 外链 JS | 绕过只看 Location 头的检测；先打统计 |
| 延迟 | `setTimeout(800)` 等 | 给统计脚本留窗口；迷惑简单爬虫 |
| 落地 | `pushState('#')` + `popstate` | 劫持后退键，延长停留 / 二次导流 |

---

## 2. 入口页：JS 延迟跳转

### 2.1 服务器行为

- 响应码多为 **`200 OK`**，不是 `301` / `302`。
- HTML 极简：viewport、`robots=noindex`、一个外链 `<script>`，`<body>` 可为空。
- 真实跳转目标写在外域 JS 里，入口 HTML 本身往往看不到落地 URL。

### 2.2 样本结构（入口 HTML）

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="robots" content="noindex">
  <title>正在加载中...请稍候</title>
  <script src="https://example-cdn.one/1x/aaaaea.js"></script>
</head>
<body></body>
</html>
```

### 2.3 样本逻辑（外链 JS）

```js
// 1) 先插统计（如百度统计）
var _hmt = window._hmt || [];
(function () {
  var hm = document.createElement("script");
  hm.src = "https://hm.baidu.com/hm.js?xxxxxxxx";
  var s = document.getElementsByTagName("script")[0];
  s.parentNode.insertBefore(hm, s);
})();

// 2) 延迟后整页跳转（样本为 800ms）
(function () {
  setTimeout(function () {
    window.location.href = "http://landing.example/12.html";
  }, 800);
})();
```

### 2.4 识别要点

- 入口页几乎无正文，却引用陌生外域 JS。
- 外链脚本内同时出现「统计 SDK」+ `setTimeout` + `location.href` / `location.replace`。
- 爬虫若不执行 JS，只能看到壳页，抓不到真实落地内容。

## 3. 落地页：后退键劫持

### 3.1 原理

1. `history.pushState(state, title, '#')` 在历史栈再压一条「当前页 + hash」记录，地址栏常出现末尾 `#`。
2. 监听 `popstate`（用户点后退会触发）。
3. 在回调里再 `location.href = 另一个广告页`，用户以为在返回，实际被甩到下一条链路。

### 3.2 样本代码（与线上同构）

```js
(function () {
  let backJumpUrl = "https://another-ads.example/88.html";
  if (backJumpUrl) {
    try {
      window.history.pushState("forward", null, "#");
      window.addEventListener(
        "popstate",
        function () {
          window.location.href = backJumpUrl;
        },
        false
      );
    } catch (err) {}
  }
})();
```

### 3.3 用户侧表现

- 打开落地页后，URL 可能变成 `.../12.html#`。
- 点一次后退 → 不回入口，而是进 `backJumpUrl`。
- 部分站点还会在点击链接时 `preventDefault` + `window.open`，并 POST 点击/下载统计接口。

### 3.4 识别要点

- 落地页脚本含 `pushState` + `popstate` + 立刻改 `location`。
- 变量名常见：`backJumpUrl`、`back_url`、`returnUrl` 等。
- 页面 `robots` 常为 `noindex, nofollow`；内容多为九宫格外链、APP 下载条。

## 4. 和「正规跳转」的对比

| 方式 | 谁执行 | 爬虫可见性 | 后退行为 |
|------|--------|------------|----------|
| HTTP 301/302 | 服务器 | Location 头直接可见 | 通常可回到上一站 |
| meta refresh | 浏览器解析 HTML | HTML 内可见 | 一般可返回 |
| `location` 立即跳 | JS | 需执行 JS | 一般可返回入口（若在历史中） |
| **本文手法** | JS 延迟 + 历史劫持 | 目标藏外链；壳页无 Location | **后退被劫持到第三站** |

## 5. 防御 / 检测思路（备忘）

面向「搜索 / 安全过滤 / 自家爬虫」时可考虑：

1. **渲染探测**：对「空壳 + 外域 script」页面用无头浏览器跑一遍，提取最终 URL。
2. **静态特征**：
   - `setTimeout` + `location.href` 同文件共现；
   - `history.pushState` + `popstate` 里再赋值 `location`。
3. **域名信誉**：入口域名与落地域、统计域、脚本 CDN 交叉关联，批量打标。
4. **行为沙箱**：若检测到 `popstate` 强制跳转，可标记为「后退劫持」类站点。
5. **合规注意**：分析他人站点仅限安全研究 / 防护；勿用于仿冒导流。

## 8. 一句话结论

**入口用「200 壳页 + 外链 JS + setTimeout」做客户端延迟跳转；落地用「pushState('#') + popstate」劫持后退。**  
检测时不要只看 HTTP 重定向头，要跟外链脚本和历史 API 行为。
