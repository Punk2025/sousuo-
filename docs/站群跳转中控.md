# 站群跳转中控（技术笔记）

> 记录日期：2026-08-03  
> 本地演示：`zhongkong/` → http://127.0.0.1:8877/admin/  
> 关联文档：[客户端延迟跳转与历史劫持](./客户端延迟跳转与历史劫持.md)

前文拆的是「单个入口怎么跳、落地怎么劫持后退」。本文记录另一半：**站群怎么批量管这些入口**——也就是所谓「中控」。

教学演示代码在 `zhongkong/`，用来理解结构，不是给真实导流用的生产系统。

---

## 1. 为什么需要中控

百度搜同一关键词会出现一批站，一点就跳到别的域名。若每个站各自改 `location.href`，域名一多就不可维护。

实际做法通常是：

```text
入口域名 A  ─┐
入口域名 B  ─┼─→  都加载同一份外链脚本 /jump.js（或中控 API）
入口域名 C  ─┘              │
                            ▼
                     中控里配好的落地 URL
```

**改中控一处配置 = 所有挂了这份脚本的入口一起变。**  
这就是「一键批量」的本质：配置下发，不是手改几百个站。

---

## 2. 分层结构

| 层级 | 职责 | 演示里对应什么 |
|------|------|----------------|
| 入口矩阵 | 大量壳站骗收录 / 接搜索流量 | 后台「入口域名」表 + `/entry/<域名>` |
| 跳转中控 | 统一落地地址、延迟、渠道 | `/admin/` + `data/config.json` |
| 外链脚本 | 入口页实际执行的跳转逻辑 | `/jump.js`（按配置动态生成） |
| 落地层 | 广告页、渠道结算、后退劫持 | `/land/12.html` 等 |
| 渠道 CID | 区分来源、方便分成 | 配置里的 `channels` / 域名上的 `channel` |

和真实黑产站群的对应关系：

- 真实环境：入口各自解析到 CDN/同批 IP，HTML 几乎相同，`<script src="https://xxx/aaaaea.js">`
- 本演示：用 `/entry/某域名` 模拟「打开某个入口」；`/jump.js` 模拟那份外链脚本

## 3. 「一键下发」在做什么

### 3.1 配置存在哪

`zhongkong/data/config.json`，主要字段：

```json
{
  "landing_url": "http://127.0.0.1:8877/land/12.html",
  "delay_ms": 800,
  "back_jump_url": "http://127.0.0.1:8877/land/hijacked.html",
  "stats_enabled": true,
  "domains": [
    {"host": "入口A.example", "channel": "12", "enabled": true, "note": "百度词包-A"}
  ],
  "channels": [
    {"cid": "12", "name": "百度-主推", "landing_path": "/land/12.html"}
  ]
}
```

后台点「一键下发」→ `POST /api/config` 写回这份 JSON。

### 3.2 入口不存跳转目标

壳页只引用脚本，例如：

```html
<script src="/jump.js?c=12"></script>
```

`/jump.js` 每次请求都按**当前配置**生成，大致等价于：

```js
setTimeout(function () {
  window.location.href = "当前中控配置的落地 URL";
}, 800);
```

因此：

1. 运营在后台改落地 URL 并下发  
2. 用户下次打开任意入口壳页  
3. 重新拉取 `/jump.js` → 自动去新目标  

无需登录几百个主机改文件。真实站群还常把脚本放独立 CDN 域名，中控只负责覆盖那一个文件或改接口返回值。

### 3.3 批量导入入口

后台支持文本批量加入，一行一个：

```text
foo.example,12,词包A
bar.example,15,词包B
```

接口：`POST /api/domains/bulk`。  
真实面板常见能力：批量绑域名、批量改解析、批量挂同一模板。

### 3.4 渠道 CID

- 域名绑定 `channel`（如 `12` / `15`）
- 落地常用 `/12.html`、`/15.html` 区分来源
- 点击广告时再带 `pid` 上报（真实样本里有 `/api/client/click`）

中控按渠道换落地路径，便于算量和结算。

## 4. 演示服务路由

启动：

```bash
cd zhongkong
python3 server.py
# http://127.0.0.1:8877/admin/
```

| 路径 | 作用 |
|------|------|
| `/admin/` | 中控后台 UI |
| `/api/config` | 读/写下发配置 |
| `/api/domains/bulk` | 批量导入入口域名 |
| `/api/preview-script` | 预览即将下发的脚本 |
| `/jump.js` | 所有入口共用的跳转脚本 |
| `/entry/<域名>` | 模拟该入口的壳页 |
| `/land/<页>` | 落地页；非劫持页带后退劫持 |

建议手测顺序：

1. 打开中控，改落地 URL 或延迟 → **一键下发**  
2. 点某行「壳页」或打开 `/entry/入口A.example`  
3. 等待跳到落地页 → 再点后退看劫持页  
4. 再改一次落地 URL 下发，不改入口页，确认新跳转已生效

## 5. 代码结构

```text
zhongkong/
├── server.py           # Flask：配置 API + 动态 jump.js + 壳页/落地页
├── data/config.json    # 中控配置（下发写入这里）
├── templates/
│   ├── admin.html      # 后台界面
│   ├── entry.html      # 入口壳页
│   └── land.html       # 落地 / 劫持页
├── static/
│   ├── admin.css / admin.js
│   └── shell.css
└── README.md
```

核心文件是 `server.py` 里的 `render_jump_js()`：配置变 → 脚本内容变 → 全站入口行为变。

## 6. 识别站群「同一中控」的指纹（备忘）

做搜索过滤 / 安全审计时，可把多入口聚成「一家伙」：

1. **同一跳转脚本域名或路径**（最强信号）  
2. 壳页 HTML 高度同构（空 body、`正在加载`、`noindex`）  
3. 落地页同一套静态目录 / 同一套点击上报 API  
4. 同一百度统计 ID，或同一 `backJumpUrl` 域名族  
5. WHOIS / 解析 IP / NS 批量重合（辅助）

有外链脚本 URL 后，再跟一次脚本内容，往往能直接看到当前统一落地地址。

## 8. 一句话结论

**站群入口可以成千上万，跳转目标通常由中控统一下发；入口只负责加载同一份脚本。**  
看到「一批百度结果点进去都跳别处」，优先查它们是否共用同一外链 JS / 同一中控域名，而不是假设每个站单独改过代码。

公开 Git 上几乎没有黑产同款完整面板；更完整的工程形态见 [相关开源与资料](./相关开源与资料.md)（短链中控、站群 CMS、劫持 PoC、检测研究）。
